# TodoList v1.1 Implementation Checklist

Date: 2026-05-17
Status: Ready for execution
Source roadmap: docs/feature-roadmap.md
Milestone scope: Features 1-4 (Smart Views, Search, Undo, Bulk Actions)

## 1) Objective

Deliver v1.1 in a predictable sequence with low regression risk.
This checklist converts roadmap intent into task-level implementation steps.
It includes:
- Task-by-task estimates.
- File-by-file change plan.
- Development order.
- QA gates per feature and per release.

## 2) Locked Decisions For v1.1

These defaults are locked for implementation unless product scope changes:
- Search query persistence: off.
- Undo depth: single-step.
- Smart views: Inbox, Today, Overdue, Upcoming (7 days), Recently Completed (7 days).
- Filter composition: Smart view AND status filter AND priority filter AND search.
- Bulk delete: always requires confirmation.

## 4) Delivery Sequence (Execution Order)

1. Phase A: Filtering foundation refactor (supports F1 and F2).
2. Phase B: F1 Smart Views.
3. Phase C: F2 Search.
4. Phase D: F3 Undo framework and integrations.
5. Phase E: F4 Multi-select and bulk actions.
6. Phase F: Hardening pass (keyboard, scaling, regressions).

Rationale:
- F1 and F2 share filter pipeline changes.
- F3 should land before F4 so bulk destructive actions can reuse undo patterns.
- F4 is last because it touches the highest number of interactions.

## 9) Risks To Watch During Implementation

- Date-boundary mistakes for Smart Views.
- Interaction conflicts between selection mode and existing row gestures.
- Undo inconsistencies if snapshot is incomplete.
- Performance issues from repeated full list rebuilds after bulk operations.

Mitigation plan:
- Keep one shared filter pipeline.
- Add explicit interaction mode checks in MainWindow event handlers.
- Snapshot before mutation, never after.
- Reuse existing in-place update patterns where possible.
